# Cybersecurity Home Lab

### Building Practical Skills in Defensive Security | Blue Team | Security Operations

A hands-on cybersecurity laboratory focused on developing practical defensive security skills through controlled attack simulations, security monitoring, threat detection, log analysis, incident investigation, and system hardening.

This project is designed to explore how cyberattacks happen, how their impact can be observed, how security threats can be detected, and how defensive mechanisms can be implemented to protect systems and networks.

Rather than jumping directly into advanced security platforms, this lab follows a fundamentals-first approach, gradually progressing towards industry-relevant security tools, technologies, and security operations workflows.

---

## 🎯 Objective

The primary objective of this laboratory is to develop a strong practical foundation in **Defensive Cybersecurity (Blue Team)**.

By building and experimenting within a controlled virtual environment, I aim to understand the relationship between offensive techniques and defensive security mechanisms.

The focus is on learning how to:

- Understand common attack techniques and their impact on systems.
- Monitor system activities and network communications.
- Analyze security events, system logs, and network traffic.
- Identify suspicious behavior and potential Indicators of Compromise (IoCs).
- Configure and strengthen host-based and network-based security controls.
- Investigate security incidents and understand response procedures.
- Develop practical threat detection and monitoring capabilities.

---

## 🖥️ Laboratory Environment

The initial environment consists of two virtual machines:

| Virtual Machine | Role | Purpose |
|---|---|---|
| Kali Linux | Attacker | Simulating controlled attacks and security testing. |
| Windows | Target | Monitoring activities, analyzing security events, and implementing defensive controls. |

The two-machine environment provides an opportunity to understand security from both offensive and defensive perspectives.

Kali Linux is used to generate controlled security events, while Windows serves as the environment for observing, analyzing, detecting, and mitigating those activities.

The laboratory will evolve as additional monitoring and security technologies are introduced.

---

## 🛡️ Technical Scope

This laboratory will progressively explore several areas of defensive cybersecurity:

- **Network Security:** Network traffic analysis, communication monitoring, network reconnaissance, and network-level security controls.
- **Windows Security:** Authentication, authorization, Windows security architecture, system auditing, and endpoint protection.
- **Firewall Management:** Inbound and outbound traffic filtering, firewall rules, and network access control.
- **Security Monitoring:** System activity monitoring, event logging, and identifying suspicious behavior.
- **Log Analysis:** Investigating Windows Event Logs, analyzing security events, and understanding system activity.
- **Threat Detection:** Recognizing attack patterns, identifying Indicators of Compromise, and developing detection techniques.
- **Incident Investigation:** Analyzing suspicious activities, understanding attack timelines, and exploring incident response procedures.
- **System Hardening:** Implementing security configurations and validating defensive mechanisms.
- **SIEM and Security Operations:** Exploring centralized logging, event correlation, security monitoring, and SOC workflows.

## 🧰 Tools and Technologies

The laboratory will gradually incorporate tools and technologies commonly used in defensive security and security operations.

Some planned technologies include:

- **Wireshark** – Network traffic analysis.
- **Windows Event Viewer** – Security event investigation.
- **PowerShell** – Windows administration, monitoring, and security configurations.
- **Sysmon** – Detailed Windows system activity monitoring.
- **Wazuh** – Security monitoring, threat detection, and log analysis.
- **SIEM Platforms** – Centralized security monitoring and event correlation.

These tools will be introduced progressively, with an emphasis on understanding their underlying concepts before relying on their capabilities.

---

## 📚 Learning Approach

Every experiment in this laboratory follows a practical, investigation-oriented approach:

1. **Understand:** Learn the underlying security concept.
2. **Simulate:** Generate controlled security events.
3. **Observe:** Examine system behavior and network activities.
4. **Analyze:** Investigate logs, identify suspicious patterns, and understand their implications.
5. **Defend:** Implement appropriate security controls and defensive mechanisms.
6. **Validate:** Evaluate the effectiveness of implemented defenses.
7. **Document:** Record technical procedures, observations, findings, and lessons learned.

The objective is not simply to execute commands or operate security tools, but to understand what happens behind the scenes and why particular defensive mechanisms are necessary.
